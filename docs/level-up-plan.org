* Status on 2026-10-04
#+INDEX: status

All seven phases are done and committed locally in writing-habit-el and writing-schedule.  Nothing has been pushed.  The decisions taken were these.

- The old private names in writing-schedule.el keep working for two releases.  They are obsolete aliases as of 0.3.1, with removal planned for 0.5.0.
- The table editing mode turns on by itself in any org file whose name is a schedule code and that holds a weekly table.
- The templates live in the scheduler.  They ship in writing-schedule's =templates/= directory, and the template commands offer them after your own.

#+CAPTION: Test counts after the level-up.

| writing-habit-el |     57 |   143 | plus 2580 parity probes against the Python table model   |

Two items remain open.  First, the scheduler's working tables are named =table-YYYY-MM-DD.org=, which is not a schedule code, so the table mode does not turn on for them and plan import records that name as the schedule code.  Second, a few legacy docstrings still draw checkdoc warnings, which =make checkdoc= lists.

* Revision note
#+INDEX: revision history

Revision 2 on 2026-10-04 adds the two scheduler repositories, writing-schedule (Emacs Lisp) and writing-schedule-py, to the survey. They change the plan in three ways. First, the overlap test, the time parser, the day parser, and the template scaffold that the Python GUI imports from writing_schedule already exist in writing-schedule.el. They are private, double-dash functions, so a new Phase 1 promotes them to a public API before anything else uses them. Second, the weekly table model in Phase 3 shrinks, because it can reuse that API instead of carrying its own copies. Third, the Schedule, Generate, and Sheets groups of the transient menu can call writing-schedule.el commands and show the matching =writing-schedule.sh= line, so the Elisp side keeps the teaching property of the GUI for both packages.

* Guiding principle
#+INDEX: design principle

The PyQt5 interface exists because a Python program has no editor around it. The Elisp port lives inside the editor, so it should not imitate the window. Each GUI feature should map onto the Emacs idiom that already does that job.

#+CAPTION: How each GUI element maps onto an Emacs idiom.
#+ATTR_LATEX: :booktabs t :center t
| PyQt5 element                         | Emacs counterpart                                         |
|---------------------------------------+-----------------------------------------------------------|
| Schedule tab grid                     | the org table in its own buffer                           |
| cell drop-down of legend codes        | =completion-at-point= over legend codes                   |
| cell tooltip with description and due | =eldoc= function                                          |
| red clash tint and yellow clear tint  | overlays fed by =writing-schedule-conflicting-identities= |
| Name, Clashes, Totals, Legend panels  | a side-window report buffer in org-mode                   |
| Insert above and below                | commands that prompt with a suggested time range          |
| Move up and down (Alt+Up, Alt+Down)   | =M-<up>= and =M-<down>= wrappers that report resectioning |
| Insert and move project in legend     | the same commands acting when point is in the legend      |
| Rename to canonical                   | a command that renames the file and visiting buffer       |
| New from template                     | =writing-schedule-new-week-from-template=, already there  |
| open the most recent table            | =writing-schedule-open-recent=, already there             |
| Open in editor                        | not needed because the table is already open in Emacs     |
| tabs of generated forms               | a transient prefix with one group per stage               |
| Command line above the run button     | the equivalent =writing-habit= or =writing-schedule.sh= line |
| session log dock                      | a =*writing-habit-log*= buffer                            |
| preview dock with Open outside        | =eww= or =browse-url= for HTML, =image-mode= for PNG      |

* Phase 1. Promote a public API in writing-schedule.el
#+INDEX: writing-schedule.el release
#+INDEX: obsolete aliases

This phase happens in the writing-schedule repository, and it unblocks everything after it.

Rename the ten functions in the table above to single-dash names. Keep each old name working through =define-obsolete-function-alias=, so any init file or script that calls the old name keeps running for one release. Write a short docstring for each that states its return shape, especially the event plist keys =:section=, =:offset=, =:start=, =:end=, and =:letter=.

Add =writing-schedule-split-row=. It splits one org table line into raw cell strings without trimming, mirroring =orgtable.split_row= in the Python port. The tracker's table model needs it to rewrite one line of a file while leaving every other byte alone, which =org-table-to-lisp= cannot do because it trims the cells.

Bump writing-schedule.el to 0.3.1 so both scheduler ports share a version number, and add ERT tests for the new names and for =split-row=. Then fix the package headers that the MELPA protocol lists.

In writing-habit-el, replace the three =declare-function= lines in =writing-habit-plan.el= with the public names and add =(writing-schedule "0.3.1")= to =Package-Requires=.

* Phase 2. Close the library gap in the tracker
#+INDEX: history command
#+INDEX: adherence series

Add =writing-habit-compare-project-mean-series= and =writing-habit-compare-category-mean-series= beside the existing =overall-series=. Both read views that already live in schema.sql, so each function is a few lines that share the range clause of =overall-series=.

Add =writing-habit-history.el=, a port of =compare/history.py=, with four public functions.

- =writing-habit-history-collect= returns the week list and the five series.
- =writing-habit-history-string= renders the same plain-text table as =render_text=, so batch output matches Python line for line.
- =writing-habit-history-org= returns the same data as org tables for the Emacs view.
- =writing-habit-history-write-plots= writes the five-panel plot through a generated matplotlib script, as =writing-habit-report-write-plot= already does for the weekly chart.

Add =history= to =writing-habit--dispatch= with =--from=, =--to=, and =--plot=.

Make =writing-habit-name-parse-legend-cell= public. Phase 3 needs it, and one rule should govern both the reader and the editor.

Port =tests/test_history.py= to ERT and add a cross-port history fixture produced by the Python package from =cross-port.db=.

* Phase 3. A Qt-free weekly table model
#+INDEX: weekly table model
#+INDEX: byte-preserving edits

Port =gui/weekly_table.py= to =writing-habit-table.el=. It holds no Qt, so it ports cleanly, and it carries the editing logic that Phase 4 needs. Keep it pure. It should take the table text and return new text or line indices, so its tests need no buffer state.

The model reads lines through =writing-schedule-split-row=, classifies rows with =writing-schedule-day-offset= and =writing-schedule-parse-time=, and computes clashes with =writing-schedule-overlaps=. It therefore owns only the logic that is new in the tracker.

- Cell and legend edits. =set-cell=, =set-legend=, =add-legend=, =insert-legend=, =remove-legend=, =next-free-code=, and =sync-legend=, which drops only the blank rows it added itself.
- Block edits. =suggest-times=, =insert-block=, =move-target=, =can-move=, =move-block=, and the resection rule that reports a change of activity.
- Legend moves. =legend-move-target=, =can-move-legend=, and =move-legend=.
- Analysis. =rows-clear-of= (it calls the scheduler's interval rule for one row against the rest), =totals= by day, project, and activity, =used-codes=, the canonical name from =writing-habit-name-encode=, and =name-matches-code=.

The Python model promises that an unchanged table saves byte for byte, that each edit rewrites one line, and that a move swaps two lines. Port those three tests first, because they keep the table readable by both schedulers. Add a test that runs the model over =projects-and-tasks.org= and checks the 44 events and 12 codes, so the tracker's view of a table never drifts from the scheduler's view.

* Phase 4. A minor mode for editing the weekly table
#+INDEX: writing-habit-table-mode
#+INDEX: overlays

Build =writing-habit-table-mode=, a minor mode that turns on in an org buffer whose file name decodes as a schedule code. It is a thin layer over the Phase 3 model.

- Completion. A =completion-at-point= function offers the legend codes in a day cell. Typing a new code adds a blank legend row through =sync-legend=.
- Eldoc. Point on a cell shows the project description, the risk tag, and the due date.
- Tints. An idle timer refreshes overlays. Cells named by =writing-schedule-conflicting-identities= get a red face. When point is in the Time column, every row that is clear of the current row gets a yellow face, and clash red wins inside a yellow row. Both faces are customizable so dark themes can override them.
- Row commands. =writing-habit-table-insert-above= and =-insert-below= prompt for a time range prefilled with the suggestion. =M-<up>= and =M-<down>= are remapped in the grid to a move that refuses the illegal cases and messages the resection, for example "Moved the 05:45-07:15 block down into Rewriting".
- Legend commands. The same keys move a legend entry when point is in the legend. =writing-habit-table-insert-project= prompts for the code (prefilled with =next-free-code=), the description, and the risk tag through =completing-read= over none, safe, and risky.
- Report panel. =writing-habit-table-report= opens a side window with four org headings, Name, Clashes, Totals, and Legend. The Clashes heading uses =writing-schedule-overlap-lines=, so its wording matches the scheduler's own warning. The mode line shows the clash count.
- File commands. =writing-habit-table-rename-to-canonical= renames the file and its buffer and refuses to overwrite another file. New tables come from =writing-schedule-new-week-from-template=, and the most recent table opens with =writing-schedule-open-recent=, so the mode adds no file-finding code of its own.

Put every command on a =C-c C-w= prefix map so it does not collide with org keys.

* Phase 5. A transient command center for both packages
#+INDEX: transient
#+INDEX: session log

Transient is built into Emacs 28 and later, so it adds no dependency. Build =writing-habit-dispatch= with one group per Python GUI tab.

#+CAPTION: Transient groups, the Elisp entry each suffix calls, and the shell line it logs.
#+ATTR_LATEX: :booktabs t :center t
| Group    | Suffix calls                                                              | Logged as                    |
|----------+---------------------------------------------------------------------------+------------------------------|
| Schedule | =writing-schedule-insert-template=, =writing-schedule-check-overlaps=     | =writing-schedule.sh= line   |
| Generate | =writing-schedule-generate=, =-generate-for-day=, =-export-ics=, =-open-week= | =writing-schedule.sh= line |
| Sheets   | =writing-schedule-timeblock-sheets=, =-timeblock-sheet-for-day=           | =writing-schedule.sh= line   |
| Plan     | =initdb=, =plan import=                                                   | =writing-habit= line         |
| Track    | =track import=, =track add=                                               | =writing-habit= line         |
| Compare  | =compare=, =dashboard=                                                    | =writing-habit= line         |
| History  | =history=                                                                 | =writing-habit= line         |
| Context  | =context set=, =clear=, =list=                                            | =writing-habit= line         |
| Seasons  | =seasons=, =name=                                                         | =writing-habit= line         |

The tracker suffixes call =writing-habit--dispatch= with the same argument list the batch CLI gets. The scheduler suffixes call the scheduler's batch functions, and they bind scheduler options for the call instead of passing flags. The Python flag =--strict= becomes a let-binding of =writing-schedule-overlap-action= to =error=, and =--no-todo= becomes a let-binding of =writing-schedule-use-todo= to nil.

Two Python scheduler options have no Elisp twin. The =--tz= option writes a VTIMEZONE through =vtimezone.py=, and =--engine reportlab= draws sheets without LaTeX. Leave both out of the menu. If the time zone matters for your calendar imports, port =vtimezone.py= into writing-schedule.el as a separate upstream task.

Each infix mirrors one option. =--db= is a file infix seeded from a =writing-habit-default-db= defcustom and from transient history. =--week= and =--day= read a date with =org-read-date=. Before a suffix runs, it writes the equivalent shell command to =*writing-habit-log*=. When a suffix writes a file, the menu offers to show it. HTML opens in =eww= with a key to open it in the browser, PNG opens in =image-mode=, and org, ICS, and TeX open as text. PDF opens with =doc-view= or =pdf-tools=, which is better than the Python preview dock can do.

The scheduler groups appear only when writing-schedule.el is loadable, as the Python GUI hides its scheduler tabs when writing_schedule is missing.

* Testing target
#+INDEX: test parity

About half of the 368 Python tests exercise the Qt layer. A fair target is that every pure Python test has an ERT twin and that every command of Phases 4 and 5 has at least one test in a temp buffer under =emacs --batch=. That puts the tracker near 250 ERT tests and adds about 20 to the scheduler for the public API.
